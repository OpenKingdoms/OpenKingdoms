# The computer player

How the original's skirmish computer player works: the state it keeps,
the profile that tunes it, how it chooses what to build and where, how
it forms groups and sends waves, whom it attacks, which attack its
units hold, and what it does when it is hit. Ticks are the original's,
30 to a second.

A `legacy:NNNNN` anchor points into the maintainers' reference of the
original, where a claim can be checked. The engine's deliberate
departures are in [MANUAL_DEVIATIONS.md](../MANUAL_DEVIATIONS.md),
cited by ID.

## The brain and its tables

Each player owns two structures for the computer player.

The brain is one per player slot, kept inside the player record and
set up at legacy:19382. It holds these, by role.

| Field | Meaning |
|---|---|
| Group slots | About 100, the strategic layer of "Groups" |
| Unit cursor | The unit the per-tick sweep resumes from |
| Group tick counter | The cadence of group updates |
| Freeze stamp | The game time until which the monarch starts no construction, see "Hits on an AI" |
| Bootstrap flag | Set during the opening seconds, it gates the opening branch |

The weight and limit table is one per player, kept in a fixed global
array indexed by player and built at legacy:19604. It is a set of
parallel arrays, each with an entry for every unit type loaded.

| Per-type array | Meaning |
|---|---|
| Build score | The 0 to 100 input of "Build decision" |
| Owned count | Instances existing, those under construction included |
| Completed count | Instances finished |
| Combat value | The type's combat strength, summed for threat |
| Static bonus | 40 when a classification field of the unit definition is zero, 20 when the type has a build list |
| Profile `weight` | 0 to 100, from the AI profile |
| Weight lock | Set once a profile line has set the weight |
| Profile `limit` | The most instances, -1 for no limit |
| Limit lock | Set once a profile line has set the limit |
| Total owned | A running total over all types |
| Visibility lists | Seen enemies, allies, enemy structures and own defences, rebuilt by the map pass |
| Base grid | The player's randomised placement grid, see "Placement" |

Which field the static bonus's first condition reads is not
established. The 40, the 20 and the build list condition are.

The threat near a point is the summed combat value of the types within
a radius (legacy:20857, the values at legacy:19803). The original keeps
a list of its own towers and a query for the ones near a point
(legacy:20985), and nothing in it calls the query.

### The per-tick flow

The per-player step runs from the 30 Hz simulation tick
(legacy:206584).

1. The think runs (legacy:19335), and when the player's controller kind
   is 2 it also updates the groups (legacy:19300).
2. The unit sweep always runs (legacy:18938). It visits
   `worldUnitCount / 30 + 1` units a tick in turn, so every unit is
   visited about once a second whatever the size of the army.
3. The attack plan is brought up to date at most once every 7 ticks
   (legacy:20616). That rebuilds the enemy lists through the map pass,
   gated by line of sight, and one time in 30 it also runs the economy
   pass, so the build decision comes about every 7 seconds. Then it
   counts again through the attack planner (legacy:20577).

The original runs the same brain in a campaign, with bootstrap branches
of its own there.

## Groups

Every unit carries a group id. A unit joins a group through a routine
that writes the id into the unit at +0xC8 (legacy:221881), and the
brain's two calls to it (legacy:18307, 18315) assign groups.

| Group id | Role |
|---|---|
| 0 | Unassigned |
| 1 | Builder pool, at bootstrap |
| 2 to 20 | Strategy and build expedition groups (legacy:16187) |
| 21 to 49, odd | Short range attack groups, radius 200000 (legacy:18250, 18632) |
| 51 to 79, odd | Long range and air raid groups, radius 500000 |
| 81 to 95 | Build queue behaviour |
| 96 | Idle |
| 0x61 and 0x62 | Mass attack, 0x62 with radius 1,000,000 |

A group's state is five slots and a mode.

| Slot | Meaning |
|---|---|
| Target id | A positive n is start position n - 1 and a negative n is sacred site -n - 1, resolved at legacy:17079 |
| Requested strength | Ratchets up over time, see "Attack waves" |
| Launch threshold | The group waits until its member count exceeds this |
| Assigned count | The members the strategy layer allotted |
| Leader or target | A unit id |
| Mode | 0 idle, 1 engaged, 2 marching |

A group keeps together by ejecting its furthest member, again and
again, until its spread is at most the member count times its radius
(legacy:15801).

## Sacred sites and start positions

The sacred sites are a table of fixed size built at map load
(legacy:128256) from every map feature whose TDF key `sacredsite` is not
zero, the key read at legacy:127337. Each record holds an active flag
and an x and z map position. These are the lodestone pads. The players'
start positions are a parallel table built at map load and indexed by
each player's start position index.

## What the computer sees

The visibility test (legacy:206797) samples the asking player's own
line of sight bitmap, which the player record carries with its width
and height, and every enemy list of the brain is gated through it
(legacy:20531-20540, 20511). The computer sees only what its line of
sight grants. The one scorer that looks past it is the wave layer's,
under "Target choice".

Nor does it cheat on mana. Its builds abort and throttle on the same
build efficiency a human's do, below 0.2333 and below 0.7
(legacy:9391, 12127, 31415). Build efficiency is the treasury's supply
fraction of [economy.md](economy.md), the pool with this frame's income
in it over what the frames being fed ask for, and 1.0 with nothing
building (legacy:235959-235983, 235975-235983). So it bites only once
the player builds more than the pool covers.

The one way a computer player differs from a human's side is the hold
on its monarch's construction after a hit, under "Hits on an AI".

## The AI profile

The profile is a file of console commands, not a structured config. It
is loaded (legacy:206363) from `ai\<aiprofile>.txt`, where `aiprofile`
is a key of the mission TDF (legacy:169124-169131), and from
`ai\default.txt` when there is none. Each line runs as a console
command, and three commands are registered for it (legacy:14991):
`plan`, `weight` and `limit`.

```
weight <unit name or category> <value>
limit <unit name or category> <count>
```

`weight` is clamped to 0 to 100 and applies to every brain. `limit` is
the most of a type, and -1 is no limit.

- The name lookup (legacy:230881) tries the exact unit type name first.
  Failing that it resolves a named category to a 512-bit type mask and
  applies to every type in the mask.
- Both commands set a lock for the type. A type left unlocked falls back
  to the FBI key `ai_weight`, a string of up to 64 characters on the
  unit definition, read at legacy:162560 and itself run as a console
  line (legacy:20193, 20238).
- A malformed line prints a parse error naming the profile
  (legacy:159930), and the rest of the file is not read.
- The profile belongs to the map or mission and is shared by every
  computer player in the game.
- The 19 shipped profiles hold only `weight`, `limit` and comments, for
  example `weight aradrag 25`, `weight arawall 0`, `limit aralode 7`,
  `limit aradrag 1` and `limit arabuild 10`.

The shipped profile weights the three Taros factories, the castle, the
dungeon and the hell, at ten and limits each to two. Eleven Taros unit
types come only from the dungeon or the hell: the fire demon, archer,
beak and witch from the dungeon, and the demon, knight, lich, mage,
mind, priest and spout from the hell. A Taros builder's list names the
castle first.

Under `[Player<i>]` in the mission TDF (legacy:169026-169131), one value
string is matched by substring for `strategic` or `passive`, for
`opponent`, `ally` or `neutral`, for a side name, for `logo <i>` and for
`massattack <seconds>`, which times 30 gives the tick of the all-out
attack. Beside it are the floats `killmul` and `timemul` and
`aiprofile <name>`.

## Build decision

The economy pass, `AIBrain_EvaluateEconomy` (legacy:19859), runs about
every 7 seconds. It scores every candidate type and then picks by
weight. Two inputs come first. The mana fraction is the player's mana
in hand over its maximum. The player is stalling when its average
income less its average spend is below -0.01, or when that difference
is about zero and the mana in hand is below 0.01.

The score of each type is adjusted in this order.

| Step | Condition | Effect |
|---|---|---|
| 1 | Always | The score starts at 1 |
| 2 | The type has a weapon section, the flag the unit loader raises at legacy:163554 | The score is set to 21, a flat base and not an addition |
| 3 | The type has the FBI key `builder`, read at legacy:162955, so walking builders and factories alike, and owned equals completed, so none is under construction | One band below is added (legacy:19951-19971) |
| 3a | Profile `limit` under 3, a type meant to be rare | 15, divided by 3 while stalling |
| 3b | Owned at most `limit / 4` | 30, divided by 2 while stalling |
| 3c | Owned at most `limit / 2` | 10, divided by the stall divisor |
| 3d | Otherwise | 6, divided by the stall divisor |
| 4 | A mana building, with the mana fraction under 0.01 | 30 more |
| 5 | A mana building, with the mana fraction under 0.30 | 30 more, on top of step 4, so 60 in all below 0.01 |
| 6 | Build cost over 500 | With `n = (cost - 500) * 0.01` truncated, while the seat's unit count is under `rand(30) + 10` the score loses `rand(min(score, n))` three times, two for a type with the `builder` key, else under `rand(40) + 40` twice or once, else under `rand(80) + 80` half of one such draw. A small army holds back dear types and a large one does not |
| 7 | Owned is 0 | The score times 4 |
| 8 | Owned is 1 | The score times 2, never with step 7 |
| 9 | The type's move class gives a minimum water depth (legacy:20039, the field filled at legacy:163200 from `MinWaterDepth` at legacy:187440, with a default of -10000), which in the shipped data only the ship classes do | The score times 3 |
| 10 | The type has the FBI key `isfeature` (legacy:20042, the flag read at legacy:163000), which is the walls | The score forced to 0 |
| 11 | A mana building, and the mana fraction is at least 0.30, or the player is not stalling, or owned exceeds completed | The score forced to 0 |
| 12 | Always, last | Clamped to 0 to 100 |

The bands of step 3 are tried in order and the first match wins. Which
stall divisor bands 3c and 3d use is not established, where 3a divides
by 3 and 3b by 2.

Step 11 makes a mana building a candidate only while the mana fraction
is under 0.30, the economy stalls and none is under construction. That
gives one mana building at a time, built only under real pressure, and
any that survives step 11 has collected the 30 of step 5. Steps 7 and 8
pace the first of a type. The first of anything is worth four times its
steady score and the second twice, which is what makes the original
vary its build rather than make one type over and over.

Step 3 is how the original comes to own more than one builder. A
walking builder has no weapon, so it starts at 1 and the band is nearly
all of its score. With the shipped profile (`weight tartb 10`,
`limit tartb 10`) a Taros builder scores 100 with none owned, 62 with
one, 31 with two, 11 with three to five and 7 above that, and 2 or less
while one is in the yard. Against a troop at 84, 42 and then 21, the
first thing a castle makes is likely a builder, the next few come
steadily, and past half the limit they stop.

The pick is `desirability = weight * score / 100` in whole numbers
(legacy:21281), so a low weight on a low score is zero and is never
drawn. The winner is chosen by weighted reservoir sampling over the
builder's build list (legacy:21300, the draw at legacy:21338-21341),
with structures and mobiles sampled apart, so the choice is random and
not a maximum. A producer's draw covers the walking builders in its list
along with the troops. A producer draws once a think, and a pick the
player's mana refuses ends the look until the next think.

The engine plans what to build next with a goal planner, priced by the
same weights and capped by the same limits, see A-003.

### Placement

The placement routine (legacy:21419) works like this.

- A type anchored to sacred sites goes to the nearest valid site
  (legacy:20447).
- Everything else gets 30 random polar attempts (legacy:20311), each
  snapped to the player's randomised grid (legacy:20283, drawn once for
  the brain at legacy:19675), and a cell a sacred site holds is
  refused. A square of the grid is `6 + 8 + rand(10)` cells by
  `6 + 8 + rand(3)`, or `9 + 8 + rand(20)` by `9 + 8 + rand(3)` for a
  type whose minimum water depth is not negative (legacy:20338), and the
  grid is set off by a fixed draw. Inside its square a footprint takes
  `rand(square - footprint - margin)`, the margin being the 6 or 9, so
  it leaves that many cells to the next square. A type too big for that
  sits at the square's corner.
- The attempts are drawn round the anchor, which is the base for the
  builder pool (legacy:17204-17206), out to a radius of five times a
  class in cells (legacy:17409-17423). That is 560 px for a builder's
  structure, 800 for a tower, 400 for a monarch's second of a type
  (legacy:17300-17307), and 800 for a type that walks and 560 for the
  monarch's (legacy:17353). A tower's distance is the sum of three draws
  of half the radius (legacy:20357-20374). The base's own size can
  widen the radius, but not until its buildings sum to far more than a
  skirmish base holds.
- The builder think then asks the pathfinder for a way from the builder
  to the site it was given, and orders the build only when there is one
  (legacy:17327 for a structure, legacy:17375 for a mobile). A site
  behind a wall is never ordered.

The radius by class (legacy:17400) is the larger of half the square
root of the group's strength and five times the class, in cells of
16 px. The class comes from a table of four, {14, 10, 7, 5}, chosen by
unit class and not by difficulty (legacy:17428). Below a quarter of a
unit's hit points the radius is divided by 5, with a floor of 160 px
(legacy:17705). The same radius is a unit's engagement radius and
bounds the wander of "Unit, factory and builder think".

The engine keeps the grid, falls back on a ring where thirty attempts
find nothing and remembers a site its builder failed at, see A-004 and
A-014. It puts a tower between home and the threat, see A-009.

## Unit, factory and builder think

- A mobile builder (legacy:17163) retreats when hurt, or else builds a
  structure, or else builds a mobile, or else falls through to the
  combat think. Its structure pick waits for a build efficiency of 0.70
  (legacy:17201).
- A factory (legacy:17983) picks and queues when it is idle and build
  efficiency is at least 0.2333 (legacy:17991). Below 0.7 a pick
  costing over 500 is passed over, all but one time in
  `2 + (cost - 500) / 300`, while the player owns fewer than
  `rand(30) + 30` units (legacy:18001-18010).
- The orders carry gates of their own, for every player. A factory's
  training order drops a product that earns nothing, `mogriumincome`
  under 0.01, below 0.2333 (legacy:9392), and a walking builder's order
  drops one below 0.7 (legacy:12127), structure or mobile. The four
  kingdoms' producers all carry `mogriumincome = 1`, so a castle or a
  Zhon trainer is never dropped there. The engine holds a Zhon walking
  producer to the pace of a castle, see A-018.
- A combat or idle unit (legacy:17624) picks a target from the list of
  enemies it sees. With nothing in sight it wanders near the base
  between two waypoints, drawn round the anchor out to the unit's class
  (legacy:17687-17703): 1120 px for a flyer, 800 for a fighter, 560 for
  a builder and 400 for an idle monarch, and a fifth of that, with
  160 px the floor, below a quarter of its hit points
  (legacy:17704-17708). The walk is a move to the anchor and on, then a
  patrol (legacy:17965-17972). So a fight it finds is a patrol's, taken
  whatever the stance and ended once the unit stands its
  `maneuverleashlength` from where it left the route with the target
  out of reach (legacy:10843-10851, 11020). Nearly every unit's leash is
  500.

### Roles

The role test (legacy:15514) sorts units for the strategy layer. Role 0
is any unit, 1 a unit under construction, 2 and 3 the producers an
expedition's builder is drawn from, 4 ground combat, 5 air (the unit
definition's air flag), 6 special (the unit definition's special flag
together with a positive special ability index) and 7 any unit that
does not build. Roles 2 and 3 pass over any unit whose type has the
`commander` key (legacy:15528-15545, the key read at legacy:163074), so
the monarch is never the builder an expedition takes. The engine may
send the monarch, see A-012 and A-017.

## Attack waves

The strategy pass, `AIBrain_UpdateStrategy` (legacy:16187), reschedules
itself `rand(30) + 15` ticks out. Each pass counts the spare units of
each role against the group thresholds, which ratchet upward over time.
When a group's requested strength is below the player's total owned
over 20 for a builder group, or over 30 for another, every threshold on
that group rises by `rand(threshold / 2) + 1`.

- Spare builders go to expansion (legacy:16503). A builder is picked,
  role 3 first and then role 2, the sacred site table is scanned, and
  the nearest safe unclaimed site is taken. A site another group already
  targets is skipped, and so is one where three times the enemies within
  50 exceeds the threat allowed. The builder gets an escort, ground or
  air or both. Every spare ground and air unit of the pass goes into the
  builder's group, and no new attack group is opened that pass
  (legacy:16320-16328). The threat allowed is that escort count. A
  builder is sent to a site only when its hit points are over three
  quarters of its maximum (legacy:16563). The engine weighs strength at
  a site rather than counting enemies, see A-008.
- One pass in 10 instead reinforces the nearest threat or support group
  that is under strength.
- Spare ground units go to a new group, the next free odd id from 21 to
  49. Its assigned count is the number of spare units, and its launch
  threshold is `rand(count * 2 / 3)`, a random fraction of the size
  meant, so waves launch early and at varying strength.
- Spare special units go to a new group in the odd band from 51 to 79.

The group dispatch, `AIGroup_UpdateAndDispatch` (legacy:18250),
reschedules itself 15 to 75 ticks out, or 150 to 1050 when the group has
no target.

- A group whose member count is at or below its launch threshold
  disbands back into its parent, since the wave was not ready.
- Otherwise it picks a target by the scorer of "Target choice"
  (legacy:15365), checks the route, and attacks (mode 1) or marches
  (mode 2).
- A live target is kept, and picked again one pass in 250. Once it dies
  the group picks the next from its own position and one of its members
  drawn at random (legacy:18293, 18343), so it goes on from where it
  won. With no target at all the group waits where it stands and looks
  again 150 to 1050 ticks later (legacy:18350).
- A member whose hit points are under its maximum over `rand(3) + 3`,
  so under a third, a quarter or a fifth, is ejected from the group on
  every pass (legacy:18364).
- The members go on at the target. None is sent to a firing position
  round its side, archers included.

The original sets every unit it commits to a fight to the offensive
stance (legacy:18889, 18905). A unit it leaves at home keeps the stance
it was born with. Its archers, priests, mages, catapults and monarch
would otherwise hold position all game.

The layer does three more things.

- Raid groups with nothing to do march to a random map edge or corner
  (legacy:18632). That is the original's scouting, and there is no
  scout logic apart from it.
- While the game time is under 31 ticks every builder is put in group 1
  (legacy:18748).
- The mass attack is a countdown for each player, seeded from the
  mission's `massattack <seconds>` and kept in the brain's table. When
  it runs out every mobile unit that is not a builder is forced into
  group 0x62, the all-out attack (legacy:18880-18895).

The engine's waves gather, weigh their strength, scout, march in step
and hold the ground they win by rules of their own, see A-006, A-007,
A-009, A-010 and A-012.

## Target choice

`AIGroup_SelectAttackTarget` (legacy:15365) is the original's one rule
for whom to attack. A group asks it with its centre and one random
member as the reference unit. It walks every player record that is
active and not marked as an ally in the asking player's alliance table,
and in each every unit that is alive, finished and attackable. Each
candidate is scored.

1. `INT_MAX` is divided by a randomly smoothed distance from the group's
   centre, `(rand(d/8) + rand(d/8)) / 4 + 1`, and then by one from the
   reference unit, `(rand(d/2) + rand(d/2)) / 4 + 1`.
2. It is divided by `rand(10) + 1 + rand(10)` when the asking player
   cannot see the candidate. Unseen units are scored, so the wave layer
   does peek at fogged positions, heavily discounted. The line of sight
   gate of "What the computer sees" covers the per-unit lists, not this
   scorer.
3. It is divided by `rand(5) + 1 + rand(5)` when the candidate's type
   carries no combat flag, by `rand(3) + 1` when it is unfinished, and
   by `rand(3) + 1` when it cannot move.
4. It is divided by `rand(share) + 1`, where `share` is the world's unit
   count over the larger of the candidate's player's unit count and 20,
   capped at 20. A player who owns a small share of the units is picked
   less often.
5. The best score that also has a route from the reference unit wins.

There is no preference for the monarch, none for the human and no
fixed nearest start. Every player not allied is in the pool. Allies are
spared only here and in return fire (legacy:15066), and the original
has no rule for helping an allied base.

The engine asks the route question off the connected ground of each
movement class and keeps one wave target for each seat, picked again
one tick in 30, see A-005. Its influence maps tilt the score, see A-002.

## Which attack a unit holds

Every armed unit of a computer seat has the attack in its hand chosen
once a visit of the per-unit sweep, about once a second
(legacy:19008-19242). A human's units keep what the player chose. The
choice goes like this.

- With nothing in its sights, a unit holding its secondary or special
  puts it away for the primary one visit in ten (legacy:19039). It keeps
  it when the attack is plain and short, no spell of stone, ice, mind
  control or paralysis and an `areaofeffect` under 200, and costs a
  tenth of the unit's own mana reserve or less (legacy:19029-19037).
- With a target, which is what the weapon in hand has taken, on a move
  order as well, the special is tried first and the secondary next.
  Either is wanted when the unit can pay for it, the target is not
  immune to its spell nor already held by its paralysis, and it serves
  the target. One with an `areaofeffect` under 51 strikes a single unit
  and always serves (legacy:19097, 19159). Under 200 it serves when the
  seen enemies within the `areaofeffect` of the target are more than
  five times the seat's own and allied units there (legacy:19124). From
  200 up it needs more than two such enemies and more than three times
  the friends (legacy:19208). A monarch under a third of its hit points
  takes the attack whatever the friends, though a wide one still needs
  its three enemies (legacy:19050).
- A wanted attack is not taken while the primary is in hand and two
  blows of it would kill the target, unless the attack is mind control
  or wide (legacy:19225-19236). With neither wanted the unit goes back
  to its primary.
- Mana spent below what the attack in hand costs drops the unit a slot
  (legacy:233957). Only this choice raises it again.

In the engine a unit without `weaponswitching` fires only its first
attack, where the original fires each weapon at a target of its own.

## Water and transports

The original's skirmish computer never loads a transport. Over the
whole brain, from legacy:14884 to legacy:20892, the only order it ever
gives is a move, at eight places, and nothing in that range reads
water, what a transport can carry, or the pickup and unload handlers a
player's own orders run (legacy:14365, 14487). Its two calls to the
group routine under "Groups" have nothing to do with transports.

What the original does about water is decline the work. A candidate the
pathfinder cannot reach from the attacker is never taken
(legacy:15473), and a group whose leader has no route does not march
(legacy:18385). A computer player on an island sits.

The engine's computer carries its army over water, trains the warships
it needs and gives a builder a ride, see A-013, A-015 and A-016, and
crosses with its waders, its fleet and its flyers, see A-019.

## Hits on an AI

- A hit on the computer's monarch, the unit with the `commander` key,
  sets the brain's freeze stamp to
  `now + 30 + rand(300) + rand(300) + rand(300)` ticks at 30 Hz, 1 to 31
  seconds (legacy:15087-15096, 15092). Only the monarch's branch of the
  builder think reads it, and the monarch starts no construction until
  it passes (legacy:17257). Other builders and the factories are not
  held.
- The same hit drops the build order the computer gave its monarch
  (legacy:15097-15100), and the return fire later in the handler
  answers the shooter (legacy:15113-15170). The frame is left to decay.
- There is no recall. Units near home fight what enters their
  engagement radius (legacy:17624).

The engine adds a base defence rule, see A-001.

## Difficulty

The original has no difficulty setting for its computer player
(legacy:21519, 1383). All its tuning is the AI profile and the
`massattack` timer. The engine's pursuit radius setting, from 50 to 200
percent, has no counterpart in the original.
